# 毕业项目：换一个领域，独立复刻同一套架构

## 为什么需要这一课

17 课练习全部在同一个 TaskFlow 代码库上做"改一个字段、加一条路由"级别的小修改。这样学出来的结果是"我能读懂并小改 TaskFlow"，但还回答不了一个更关键的问题：**离开这份代码，你能不能独立搭一个新的后端？**

这一课没有代码快照，也不打分。它是一面镜子：你自己选一个陌生领域，从空文件夹开始，把 01～17 课学到的东西重新组装一遍。组装不起来的地方，就是真正没学会的地方。

## 什么时候做

完成第 17 课之后。不要提前做——你还没学到 Guard、Migration、E2E 之前，这份清单里一半的要求你都无法理解为什么需要。

## 规则

1. **换领域，不要抄 TaskFlow**。选下面任意一个候选题目，或者你自己想一个（原则：至少有两种资源、其中一种从属于另一种，类似 Project → Task 的从属关系）。
2. **可以看课程 README 和官方文档，不要看 `../nestjs-learning-demo` 的源码**。卡住超过 30 分钟再去对照，且只看结构、不复制粘贴。
3. **新建一个全新目录**（比如 `~/practice/my-capstone`），用 `nest new` 或手写 `package.json` 从零开始，不要在 `lessons/17-production` 里改。
4. **允许失败**。这不是考试，是诊断。写不出来的部分，回到对应课程重学，比硬憋出一份能跑但自己说不清原理的代码更有价值。

## 候选题目（任选其一）

| 题目 | 两级资源关系 | 一个能体现业务规则的点 |
| --- | --- | --- |
| 个人记账本 | 账本（Ledger）→ 交易记录（Transaction） | 交易金额不能为负；删除账本前必须先清空交易 |
| 图书借阅系统 | 书架（Shelf）→ 图书（Book） | 借出中的图书不能被删除；同一本书不能被两个人同时借 |
| 习惯打卡器 | 习惯（Habit）→ 打卡记录（CheckIn） | 同一天不能重复打卡；连续打卡天数需要计算得出，不是存储字段 |
| 留言板 | 话题（Topic）→ 留言（Comment） | 只有作者本人能编辑或删除自己的留言 |

## 验收清单：对照着课程地图逐项打勾

不要求一次性全部做完；每完成一组，回头看看对应课次的"自测题"能不能脱稿回答。

**基础骨架（对应 01～05 课）**

- [ ] `main.ts` 启动，至少一个 Controller 能响应 GET 请求
- [ ] 至少两个独立 Module，边界清晰（比如 `LedgersModule` 和 `TransactionsModule`，而不是全塞进 `AppModule`）
- [ ] 顶层资源和从属资源都有内存版 CRUD（先不接数据库）

**输入与错误处理（对应 06～08 课）**

- [ ] 用 DTO + `class-validator` 校验请求体，非法输入返回 400
- [ ] 至少一个自定义业务异常（比如"金额不能为负"），经过统一 Filter 处理成一致的错误结构
- [ ] 有一个 Middleware 或 Interceptor 记录请求日志（不要求多复杂，能看出请求进入和离开即可）

**持久化（对应 09～11 课）**

- [ ] 配置从 `ConfigModule` 读取，不在业务代码里直接读 `process.env`
- [ ] 用 TypeORM + SQLite 替换内存实现，至少两张表，一对多关系
- [ ] 关系变更通过 Migration 完成，而不是 `synchronize: true`

**账号与权限（对应 12～13 课）**

- [ ] 注册/登录接口，密码用 bcrypt 哈希，签发 JWT
- [ ] 全局 Guard 保护业务接口，未登录请求返回 401
- [ ] 从属资源的所有权判断写在查询条件里（比如 `WHERE ownerId = :userId`），不是查出来再在 Controller 里用 `if` 判断

**打磨（对应 14～17 课）**

- [ ] 列表接口支持分页，返回 meta（page/limit/total）
- [ ] 用 Swagger 能看到完整的请求/响应合同
- [ ] 至少 3 个 Service 单元测试（含一个 mock 掉 Repository 的用例）
- [ ] 至少 2 个 E2E 测试，覆盖一条"注册 → 登录 → 操作资源"的完整故事
- [ ] 加上健康检查路由和基础安全头（Helmet/CORS 任选其一说清楚为什么需要）

## 自我诊断：卡住了怎么办

卡住是这一课唯一的目的所在——它告诉你哪一课没学扎实。按下表回原课复习，不要跳过直接抄答案：

| 卡住的现象 | 回去重学 |
| --- | --- |
| 不知道 Controller 和 Service 该怎么分工 | 第 03～04 课 |
| DTO 写了但校验没生效 | 第 06 课 |
| 关系字段建出来了但删除父资源时报外键错误 | 第 11 课 |
| 登录能拿到 token，但带着 token 访问接口还是 401 | 第 12～13 课 |
| Guard 能挡住匿名请求，但用户能看到别人的数据 | 第 13 课"所有权不是 Controller 的 if" |
| 单元测试里 mock 之后不知道断言什么 | 第 15 课 |

## 完成标准

不是"能跑通几个 curl"，而是：

- 你能不看这份清单，向别人讲清楚你的资源模型、认证方式和权限判断逻辑分别写在哪一层。
- 你能指出这个项目和 TaskFlow 之间"哪些是可复用的模式，哪些是因为业务不同而必须不一样"。
- 换第三个领域（不在候选列表里的），你有信心独立开一个新项目重复这套流程，而不需要再回头翻课程 README。

做到这三条，代表你已经从"学完一门课程"走到了"能独立做一个后端项目"。
