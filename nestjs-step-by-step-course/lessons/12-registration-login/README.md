# 第 12 课：注册、登录、密码哈希与 JWT

## 学习目标

- 区分认证与授权。
- 理解密码哈希、通用登录错误和 JWT `sub` 的作用。
- 确保密码原文和哈希都不会进入公开响应。

本课分两轮阅读：第一轮只追注册链路，第二轮再追登录链路。最后比较两条链路共同调用的 token 响应方法。

## 先把两个概念分开

到这一课之前，谁都能操作任何数据，因为程序压根不知道"是谁"在发请求。这一课开始让用户能注册、登录，先把两个词分清楚：

- 注册/登录，证明"你是谁"，叫 Authentication（认证）。
- 能不能访问某个项目，判断"你能做什么"，叫 Authorization（授权）。

这一课只做认证、发一个令牌，下一课才会用这个令牌去挡权限。

## 注册链路

```text
RegisterDto -> bcrypt hash -> User.passwordHash -> JWT { sub: user.id }
```

密码永远不能明文存进数据库，要用一种叫哈希的方式处理过（简单说是一种不可逆的加密，存的是加密后的结果，就算数据库泄露，别人也拿不到原始密码），响应里也绝不能出现这个哈希值。登录成功后发的 JWT 令牌里，只放一个稳定不变的用户 ID——邮箱、昵称这些以后可能会改的信息，不应该被"焊死"在令牌里。

## 登录链路

1. 邮箱统一转成小写再去查。
2. 用 bcrypt 把输入的密码和存的哈希做比较。
3. 成功就发 JWT；不管是密码错了还是账号压根不存在，统一回一句"邮箱或密码错误"。

哪怕这个邮箱根本不存在，程序也会拿一个固定的假哈希去比较一次，为的是让"账号存在但密码错"和"账号根本不存在"这两种情况耗费的时间看起来一样——不然别人能通过响应速度的差异，反推出哪些邮箱是真实注册过的。

## 运行

```bash
npm run lesson -- 12
curl -X POST http://localhost:3000/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"student@example.com","displayName":"学习者","password":"LearnNest123!"}'
```

然后用同一邮箱密码请求 `POST /auth/login`。检查响应只有公开用户字段和 `accessToken`。

## bcrypt 的 72 字节细节

bcrypt 只处理前 72 个 UTF-8 字节，72 个汉字远超过 72 字节。因此 DTO 除字符长度外还使用 `MaxByteLength`，避免两个不同长密码因相同前缀而等价。

## 课堂练习

尝试重复注册、错误密码、不存在邮箱和超长中文密码，记录各自状态码，并确认响应不泄露密码哈希。

## 常见错误

- 加密和哈希概念混用：密码验证需要单向哈希，不需要可解密密文。
- JWT 放入密码哈希、邮箱等不必要信息。
- 不存在用户时立刻返回，产生明显的登录耗时差异。
- 只限制 72 个字符，忽略 bcrypt 的 72 个 UTF-8 字节边界。

## 完成标准

- 数据库里没有明文密码。
- 登录失败返回统一 401。
- JWT payload 只包含 `sub`。
- 你能清楚区分认证与授权。
